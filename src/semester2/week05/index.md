# 5주차: 다중 상속과 MRO - 복잡한 계층 구조 해결 🕸️

지난 시간에는 하나의 부모로부터 상속받는 단일 상속을 배웠습니다. 하지만 파이썬은 여러 개의 부모 클래스로부터 동시에 상속받는 **다중 상속(Multiple Inheritance)**을 지원합니다. 여기서 아주 흥미롭고 복잡한 문제가 발생하는데, 바로 **MRO**입니다.

---

## 1. 다중 상속 (Multiple Inheritance)

다중 상속은 한 클래스가 두 개 이상의 부모 클래스로부터 속성과 메서드를 물려받는 것입니다.

```python
class Flyer:
    def fly(self): print("하늘을 납니다.")

class Swimmer:
    def swim(self): print("물속을 헤엄칩니다.")

# 두 클래스를 모두 상속받음
class Duck(Flyer, Swimmer):
    pass

donald = Duck()
donald.fly()  # 결과: 하늘을 납니다.
donald.swim() # 결과: 물속을 헤엄칩니다.
```

---

## 2. 다이아몬드 문제 (The Diamond Problem)

다중 상속에서 가장 문제가 되는 상황이 바로 **다이아몬드 상속**입니다.

![다이아몬드 상속과 MRO](./img/mro_diamond.svg)

**상황:**
1.  클래스 `A`에 `greet()` 메서드가 있습니다.
2.  클래스 `B`와 `C`가 `A`를 상속받고, 각각 `greet()`를 오버라이딩했습니다.
3.  클래스 `D`가 `B`와 `C`를 모두 상속받았습니다.

**질문:** `D`의 객체에서 `greet()`를 호출하면, `B`의 것이 실행될까요, `C`의 것이 실행될까요?

---

## 3. MRO (Method Resolution Order)

파이썬은 이 문제를 해결하기 위해 **MRO (메서드 결정 순서)**라는 규칙을 사용합니다. 파이썬은 **C3 Linearization**이라는 알고리즘을 통해 상속 계층을 하나의 선형 리스트로 만듭니다.

### 3.1 MRO 탐색 규칙
파이썬의 MRO는 기본적으로 다음과 같은 원칙을 따릅니다.
1.  **자식 클래스**를 가장 먼저 확인합니다.
2.  **부모 클래스**들을 **왼쪽에서 오른쪽 순서**로 확인합니다.
3.  **상위 클래스**로 올라가기 전에 모든 **형제 클래스**를 먼저 확인합니다.

**위 다이아몬드 구조의 MRO 순서:**
`D` $\rightarrow$ `B` $\rightarrow$ `C` $\rightarrow$ `A`

### 3.2 MRO 확인 방법
파이썬에서는 `__mro__` 속성이나 `mro()` 메서드를 통해 이 순서를 직접 확인할 수 있습니다.

```python
print(Duck.mro()) 
# 결과: [<class '__main__.Duck'>, <class '__main__.Flyer'>, <class '__main__.Swimmer'>, <class 'object'>]
```

---

## 4. 🔍 Deep Dive: `super()`와 MRO의 관계

우리가 4주차에 배운 `super()`는 단순히 "내 부모"를 호출하는 것이 아닙니다. 실제로는 **MRO 리스트에서 내 다음 순서에 있는 클래스**를 호출하는 것입니다.

따라서 다중 상속 구조에서 `super().method()`를 호출하면, 설계된 MRO 순서에 따라 체인처럼 메서드들이 호출됩니다. 이를 통해 다이아몬드 구조에서도 중복 호출 없이 모든 부모의 기능을 안전하게 실행할 수 있습니다.

## 🔍 Deep Dive: C3 선형화(Linearization) 알고리즘과 super()의 진정한 정체

다중 상속에서 부모 클래스의 메서드 탐색 순서를 결정하는 것은 생각보다 매우 복잡합니다. 파이썬은 C3 선형화(C3 Linearization) 알고리즘을 사용합니다.
- **C3 선형화**: 다음의 세 가지 규칙을 완벽하게 만족하는 하나의 순서 리스트를 도출하는 수학적 절차입니다.
  1. **자식 클래스**가 부모 클래스보다 먼저 탐색되어야 한다.
  2. 여러 부모 클래스를 상속받을 때, **상속 목록에 적힌 순서(왼쪽 ➡️ 오른쪽)**를 그대로 지켜야 한다.
  3. 부모 클래스가 공유하는 공통 조상(예: `object` 또는 공통 부모)은 모든 분기가 끝나기 전까지 먼저 탐색되어서는 안 된다. (다이아몬드 상속 구조 해결)
- **`super()`의 재정의**: `super()`는 단순한 "내 직계 부모"를 호출하는 함수가 아닙니다. **"이 인스턴스의 MRO 리스트에서 내 바로 다음(Next) 클래스를 찾아라"**라는 화살표 역할을 합니다. 다중 상속 하에서 `super()`는 다이아몬드의 반대편 날개 클래스를 호출할 수 있음을 명심해야 합니다.

## ☕ Java vs Python 스나이퍼 비교

### 다중 상속 모델의 비교
*   **Java**: 클래스의 다중 상속을 허용하지 않습니다(단일 상속만 지원). 대신 **인터페이스(Interface)**를 여러 개 구현(implements)하는 방식을 통해 다중 상속에서 오는 모호성 문제(예: 다이아몬드 문제 - 어떤 부모의 메서드를 써야 할지 결정 곤란한 문제)를 원천적으로 배제합니다.
*   **Python**: 유연성을 극대화하여 클래스의 다중 상속을 전적으로 허용합니다. 대신 이로 인해 발생할 수 있는 다이아몬드 충돌은 인터프리터가 **MRO(Method Resolution Order)**를 통해 C3 알고리즘에 기초하여 단일 탐색 리스트로 깔끔히 정제하고 단선적으로 메서드를 처리합니다.

## 코딩 영단어 학습 📝

*   **`Multiple Inheritance`**: 다중 상속. (하나의 자식 클래스가 두 개 이상의 서로 다른 부모 클래스로부터 기능을 동시에 물려받는 상속 기법입니다.)
*   **`MRO` (Method Resolution Order)**: 메서드 탐색 순서. (다중 상속된 복잡한 계층 구조 속에서 호출된 메서드를 어느 클래스부터 순서대로 찾아가 확인해야 할지 결정하는 인터프리터의 검색 로드맵입니다.)
*   **`Linearization`**: 선형화. (복잡하게 얽힌 트리/그래프 상속 구조를 일렬(1차원 배열)로 순차 정돈하는 수학적 처리 과정입니다.)

## 📖 교재 상세 학습: 8. 메타 클래스의 이해

## 8. 메타 클래스의 이해

지금까지 우리는 붕어빵 틀(클래스)로 붕어빵(인스턴스)을 찍어냈습니다. 그런데 문득 궁금증이 생깁니다. **"도대체 그 붕어빵 '틀' 자체는 누가 찍어내는 거지?"** 
이 호기심의 종착지에 바로 **메타 클래스(Metaclass)**라는 개념이 기다리고 있습니다.

### 8.1 붕어빵 틀 공장: `type`

우리가 객체의 자료형을 확인할 때 무심결에 쓰는 `type()` 함수는 사실 함수가 아니라 **파이썬의 가장 거대한 공장(메타 클래스)**입니다. 

우리가 에디터에 `class MyClass:` 라고 치면, 파이썬은 내부적으로 몰래 `type` 공장을 가동시켜 `MyClass`라는 붕어빵 틀을 쇳물에서 주조해냅니다. 즉, 파이썬의 모든 클래스는 `type`이 만들어낸 하나의 인스턴스에 불과합니다.

```python
# 일반적인 붕어빵 틀(클래스) 정의
class Dog:
    name = "강아지"

# 이 '틀' 자체의 자료형(누가 만들었지?)을 물어봄
# [결과] <class 'type'> -> "type 이라는 메타 클래스가 만들었습니다."
print(type(Dog)) 
```

---

### 8.2 코딩 없이 클래스 찍어내기

메타 클래스 `type`의 진짜 힘은 코드 문자열과 딕셔너리만으로 **런타임(실행 중)에 동적으로 새로운 클래스를 창조**할 수 있다는 점입니다. 

`type(이름, 상속받을부모튜플, 속성딕셔너리)` 형태로 설계도를 넘겨주면, 눈 깜짝할 새에 새로운 클래스가 뚝딱 튀어나옵니다.

```python
# 1. 속성들을 담은 딕셔너리 준비
namespace = {
    'name': '스카이넷',
    'hp': 9999
}

# 2. type 메타 클래스를 가동하여 'Robot' 이라는 새로운 클래스 창조!
# (상속받을 튜플이 비어있으므로 (object,) 가 기본값)
RobotClass = type('Robot', (), namespace)

# 마치 'class Robot:' 으로 만든 것과 똑같이 완벽하게 작동합니다.
terminator = RobotClass()
print(terminator.name) # 스카이넷
print(terminator.hp)   # 9999
```

---

### 8.3 나만의 메타 클래스 만들기

기본 공장인 `type` 대신 우리가 직접 **맞춤형 붕어빵 틀 공장(Custom Metaclass)**을 지을 수도 있습니다. 
`type`을 상속받아 나만의 메타 클래스를 작성한 뒤, 일반 클래스를 만들 때 `metaclass=` 옵션을 달아주면 파이썬은 기본 공장 대신 내 공장으로 주문서를 넘깁니다.

이 기법은 웹 프레임워크(Django 등) 핵심 개발자들이 ORM 테이블 구조를 마법같이 생성할 때 사용하는 궁극기 중 하나입니다.

```python
# 1. 나만의 붕어빵 틀 공장 건축 (반드시 type을 상속)
class MyCustomMeta(type):
    # 클래스가 탄생(?)하기 직전에 호출됨
    def __new__(mcs, name, bases, namespace):
        print(f"[메타 공장] '{name}' 클래스 조립을 시작합니다...")
        return super().__new__(mcs, name, bases, namespace)

# 2. 클래스 주문 시 내 공장에 하청 주기
class User(metaclass=MyCustomMeta):
    pass
    
# 화면 출력: [메타 공장] 'User' 클래스 조립을 시작합니다...
```
