# 13주차: 유닛 테스트 - 버그 없는 코드 만들기 🧪

우리는 지금까지 코드를 짜고 직접 실행해서 확인하는 방식으로 개발했습니다. 하지만 프로그램이 커지면 모든 경우의 수를 직접 테스트하는 것은 불가능합니다. 이때 사용하는 것이 **유닛 테스트(Unit Test)**입니다.

---

## 1. 유닛 테스트 (Unit Test)란?

유닛 테스트는 프로그램의 가장 작은 단위(주로 함수나 메서드)가 의도한 대로 정확히 작동하는지 확인하는 테스트입니다.

### 1.1 왜 테스트 코드를 짜야 할까요?
1.  **회귀 테스트 (Regression Test):** 새로운 기능을 추가했을 때, 기존에 잘 작동하던 기능이 망가지지 않았는지 즉시 확인할 수 있습니다.
2.  **설계 개선:** 테스트하기 쉬운 코드를 짜려고 노력하다 보면, 자연스럽게 결합도가 낮고 응집도가 높은 좋은 설계가 나옵니다.
3.  **문서 역할:** 테스트 코드를 보면 이 함수에 어떤 입력이 들어가고 어떤 결과가 나와야 하는지 명확히 알 수 있습니다.

---

## 2. 파이썬의 테스트 프레임워크: `pytest`

파이썬 표준 라이브러리인 `unittest`도 있지만, 최근에는 더 간결하고 강력한 `pytest`를 훨씬 많이 사용합니다.

### 2.1 `pytest` 기본 사용법
`pytest`는 함수 이름이 `test_`로 시작하는 모든 함수를 찾아 자동으로 실행합니다.

```python
# calculator.py
def add(a, b):
    return a + b

# test_calculator.py
def test_add():
    assert add(1, 2) == 3
    assert add(-1, 1) == 0
    assert add(-1, -1) == -2
```

**실행 방법:**
```bash
pip install pytest
pytest test_calculator.py
```

## 3. 🔍 Deep Dive: TDD (Test Driven Development)

대학 전공 수준의 핵심 방법론인 **테스트 주도 개발(TDD)**에 대해 알아봅시다. TDD는 코드를 짜는 순서를 완전히 뒤바꾼 방식입니다.

![TDD 사이클](./img/tdd_cycle.svg)

**TDD의 3단계 사이클:**
1.  **Red (실패):** 구현하려는 기능의 테스트 코드를 먼저 작성합니다. 당연히 기능이 없으므로 테스트는 실패합니다.
2.  **Green (성공):** 테스트를 통과시키기 위한 **최소한의 코드**만 작성합니다.
3.  **Refactor (개선):** 테스트가 성공했다면, 코드의 중복을 제거하고 가독성을 높이는 등 최적화를 진행합니다.

이 과정을 반복하면, 테스트 코드가 곧 설계서가 되며 버그가 거의 없는 매우 견고한 소프트웨어를 만들 수 있습니다.

## 🔍 Deep Dive: 단위 테스트에서 Mock과 Patch의 작동 원리와 런타임 메모리 가로채기

단위 테스트를 진행할 때 외부 날씨 API 서버를 연동하거나 데이터베이스를 직접 건드리는 것은 매우 위험하고 느립니다. 이때 Mock(가짜 객체)을 사용합니다.
- **`unittest.mock.patch`**: 런타임에 파이썬 내부 모듈 검색 캐시나 타겟 객체의 힙 메모리 주소(네임스페이스)를 추적하여, 실제 클래스/함수가 있던 자리를 **`MagicMock`** 가짜 객체로 순식간에 교체(Overwriting)해 버리는 기법입니다.
- **원격 호출 차단**: 테스트 블록이 실행되는 동안 가짜 모듈이 대신 동작하므로 원격 서버에 요청을 날리지 않고도 "만약 날씨 API가 에러(500)를 내뿜는다면 어떻게 반응할 것인가?" 같은 최악의 시나리오를 로컬 가상 메모리에서 안전하게 시뮬레이션할 수 있습니다.

## ☕ Java vs Python 스나이퍼 비교

### 모의 객체(Mock) 라이브러리와 프레임워크 차이
*   **Java**: 모의 객체를 생성하기 위해 **Mockito** 같은 강력한 서드파티 라이브러리를 의존성에 추가해야 합니다. 자바는 정적 타입 언어이므로 컴파일 시점에 타입 구조가 완성되어 있어 런타임에 힙 공간 메모리를 마음대로 덮어씌울 수 없습니다. 따라서 가짜 인터페이스 프록시(Proxy) 객체를 우회 생성하여 바인딩하는 무겁고 복잡한 리플렉션 기술을 내부적으로 씁니다.
*   **Python**: 언어의 내장 라이브러리에 `unittest.mock`이 기본 탑재되어 있습니다. 런타임 딕셔너리(`__dict__`)를 마음대로 뜯어고칠 수 있는 지극히 유연한 객체 특성을 활용하여, `patch` 데코레이터 단 한 줄로 아무 클래스나 즉석에서 가짜 스텁(Stub)으로 변형해 활용합니다.

## 코딩 영단어 학습 📝

*   **`Unit Test`**: 단위 테스트. (프로그램 내부의 가장 작은 단위인 개별 함수나 클래스 메서드가 기획대로 완벽하게 작동하는지 떼어내어 검증하는 고속 품질 테스트 기법입니다.)
*   **`Mocking`**: 모의 처리, 모킹. (네트워크 통신이나 DB 트랜잭션 등 테스트 대상이 의존하는 무겁고 불확실한 외부 자원을 통제 가능한 가짜 객체(Mock)로 대체하는 모의 실험 기술입니다.)
*   **`Fixture`**: 픽스처. (테스트를 실행하기 전에 필요한 객체나 데이터베이스의 가상 상태를 미리 깔끔하게 준비해 두는 테스트 셋업 장치입니다.)
