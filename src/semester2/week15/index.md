# 15주차: 배포 및 패키징 (2) - PyPI에 내 라이브러리 공개하기 🌍

지난 시간에는 내 코드를 배포 가능한 형태(`.whl`)로 빌드하는 법을 배웠습니다. 이제 이 파일을 전 세계 파이썬 개발자들이 사용할 수 있도록 **PyPI (Python Package Index)**에 업로드하는 과정을 배웁니다.

---

## 1. PyPI (Python Package Index)란?

PyPI는 파이썬의 공식 라이브러리 저장소입니다. 우리가 `pip install`을 통해 설치하는 모든 라이브러리는 기본적으로 이 PyPI 서버에서 다운로드됩니다.

### 1.1 배포 과정 (Workflow)
1.  **코드 작성 및 테스트:** 기능 구현 및 유닛 테스트 완료.
2.  **빌드:** `pyproject.toml`을 기반으로 `.whl` 파일 생성.
3.  **업로드:** `twine`이라는 도구를 사용하여 PyPI 서버에 업로드.
4.  **설치:** 전 세계 사용자가 `pip install`로 설치.

---

## 2. Twine을 이용한 업로드

`twine`은 빌드된 패키지를 안전하게 PyPI에 업로드하기 위한 표준 도구입니다.

**업로드 단계:**
1.  `pip install twine` 설치
2.  PyPI 계정 생성 및 API 토큰 발급
3.  `twine upload dist/*` 실행

---

## 3. 버전 관리: 시맨틱 버저닝 (Semantic Versioning)

라이브러리를 배포할 때 가장 중요한 것이 **버전 번호**입니다. 무작정 숫자를 올리는 것이 아니라, 전 세계적인 약속인 **시맨틱 버저닝(SemVer)**을 따릅니다.

**형식: `MAJOR.MINOR.PATCH` (예: 1.2.3)**

- **MAJOR:** 기존 버전과 호환되지 않는 **파괴적 변경**이 있을 때 올립니다. (예: 함수 이름 변경, 필수 인자 추가)
- **MINOR:** 기존 버전과 호환되면서 **새로운 기능**이 추가되었을 때 올립니다.
- **PATCH:** 기능 추가 없이 **버그 수정**만 이루어졌을 때 올립니다.

## 🔍 Deep Dive: 시맨틱 버저닝(Semantic Versioning)과 PyPI 릴리즈 자동화의 정수

안정적인 라이브러리를 운영하기 위해서는 버전 관리가 필수적입니다.
- **시맨틱 버저닝 2.0.0 (SemVer)**: `Major.Minor.Patch` 세 자리 숫자로 규격을 통제합니다.
  - **Major (주 버전)**: 하위 호환성이 완전히 깨지는 대규모 API 개편이나 구조 파괴 시 변경합니다. (예: `1.0.0` ➡️ `2.0.0`)
  - **Minor (부 버전)**: 기존 기능의 하위 호환성을 완벽히 유지하면서 유용한 새 기능을 추가할 때 올립니다. (예: `1.1.0` ➡️ `1.2.0`)
  - **Patch (패치 버전)**: API 규격을 건드리지 않고 내부의 버그 수정이나 핫픽스를 적용할 때 올립니다. (예: `1.2.1` ➡️ `1.2.2`)
- **PyPI 배포 자동화**: 개발자가 GitHub에 코드를 커밋하고 릴리즈 태그(`v1.2.0`)를 붙이면, GitHub Actions 워크플로우가 자동으로 가상 서버를 띄워 빌드하고, PyPI API 토큰을 인증해 전 세계로 모듈을 자동 배포하는 CI/CD 자동 팩토리가 현대 오픈소스 배포의 표준입니다.

## ☕ Java vs Python 스나이퍼 비교

### 중앙 패키지 유통 마켓과 버전 관리
*   **Java**: 빌드된 아티팩트(`JAR` 또는 `WAR`)를 Maven Central, Sonatype 또는 회사 내부의 Nexus Repository 등의 원격 저장소에 배포합니다. 라이브러리의 중복 배포 방지 및 서명 검증을 위해 엄격한 PGP GPG 서명 절차를 요구합니다.
*   **Python**: 전 세계 단일 중앙 포털인 **PyPI(pip)**로 직결되어 배포가 매우 대중적이고 간단합니다. 개발자는 `twine` 도구를 사용해 PyPI 계정 API 인증 토큰을 던지는 간단한 커맨드 명령어 한 줄만으로도 전 세계 누구나 다운받아 쓸 수 있는 글로벌 휠 패키지를 즉시 퍼블리싱할 수 있습니다.

## 코딩 영단어 학습 📝

*   **`Semantic Versioning`**: 시맨틱 버저닝, 의미론적 버전 관리. (코드의 변경 규모와 호환성 수준에 따라 버전 숫자를 논리적 규칙(메이저.마이너.패치)에 맞추어 부여하는 세계적 합의 규격입니다.)
*   **`Release`**: 출시, 릴리즈. (테스트가 완전히 통과되어 최종 사용자나 다른 프로그래머가 안심하고 내려받아 사용할 수 있도록 배포판을 공식 배포 시장에 출시하는 마일스톤 단계입니다.)
*   **`CI/CD` (Continuous Integration / Continuous Deployment)**: 지속적 통합 / 지속적 배포. (코드가 커밋될 때마다 자동으로 빌드, 테스트를 수행하고 서비스 서버나 패키지 마켓에 자동으로 릴리즈까지 도맡아 배달하는 현대 소프트웨어 공학의 자동화 배스크 파이프라인입니다.)
