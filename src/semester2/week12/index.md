# 12주차: 타입 힌팅 (Type Hinting) - 코드의 문서화와 안정성 🏷️

파이썬은 동적 타이핑 언어입니다. 변수를 만들 때 타입을 정하지 않아도 되기에 매우 편리하지만, 프로젝트가 커지면 **"이 함수에 도대체 뭘 넣어야 하지?"**라는 혼란이 생깁니다. 이를 해결하기 위해 도입된 것이 **타입 힌팅(Type Hinting)**입니다.

---

## 1. 타입 힌팅이란?

타입 힌팅은 변수나 함수의 매개변수, 반환값에 **어떤 타입이 들어와야 하는지 명시**하는 것입니다.

![타입 힌팅 효과](./img/type_hinting.svg)

### 1.1 기본 문법
```python
# 타입 힌트가 없는 경우
def greet(name):
    return "Hello, " + name

# 타입 힌트를 적용한 경우
def greet(name: str) -> str:
    return "Hello, " + name
```
- `name: str`: 매개변수 `name`은 문자열(`str`)이어야 함을 의미합니다.
- `-> str`: 함수의 결과값(반환값)이 문자열(`str`)임을 의미합니다.

---

## 2. `typing` 모듈 활용 (심화)

단순한 `int`, `str` 외에 리스트나 딕셔너리 같은 복잡한 구조의 타입을 명시하려면 `typing` 모듈을 사용합니다.

### 2.1 주요 타입 힌트
- `List[T]`: T 타입의 요소들을 가진 리스트 (예: `List[int]`)
- `Dict[K, V]`: K 타입의 키와 V 타입의 값을 가진 딕셔너리 (예: `Dict[str, int]`)
- `Optional[T]`: T 타입일 수도 있고, `None`일 수도 있는 경우
- `Union[T1, T2]`: T1 또는 T2 타입 중 하나인 경우

```python
from typing import List, Dict, Optional, Union

def process_scores(scores: List[int]) -> float:
    return sum(scores) / len(scores)

def find_user(user_id: int) -> Optional[str]:
    users = {1: "지니", 2: "철수"}
    return users.get(user_id) # 찾으면 str, 못 찾으면 None 반환
```

## 3. 🔍 Deep Dive: 타입 힌트는 강제성이 없다?

여기서 매우 중요한 점이 있습니다. 파이썬의 타입 힌트는 **'힌트'**일 뿐입니다. 즉, `int`라고 적어놓고 `str`을 넣어도 파이썬 인터프리터는 에러를 내지 않고 그대로 실행합니다.

**그렇다면 왜 쓸까요?**
1.  **가독성:** 코드를 읽는 사람이 타입을 즉시 알 수 있어 문서 역할을 합니다.
2.  **IDE 지원:** VS Code 같은 에디터가 잘못된 타입을 넣었을 때 경고를 띄워줍니다.
3.  **정적 분석 도구 (mypy):** `mypy` 같은 도구를 사용하면, 프로그램을 실행하기 전에 코드 전체를 스캔하여 타입 오류를 찾아낼 수 있습니다.

**mypy 사용법:**
```bash
pip install mypy
mypy my_script.py
```

## 🔍 Deep Dive: 프로토콜(Protocol)을 이용한 정적 덕 타이핑과 구조적 서브타이핑

파이썬은 원래 실행 중에 타입을 평가하는 동적 타입 언어입니다. 하지만 타입 힌팅과 `typing.Protocol`(PEP 544)을 도입하면서 새로운 전기를 맞았습니다.
- **구조적 서브타이핑 (Structural Subtyping)**: 부모 클래스를 직접 상속받지 않아도(이름 기반 명시가 아니어도), 클래스가 프로토콜에 정의된 특정한 공통 메서드 원형을 갖추고만 있다면 자동으로 그 타입의 자식(Subtype)으로 인정해 버리는 기법입니다.
- **정적 덕 타이핑**: 이를 통해 런타임의 유연한 덕 타이핑 철학을 그대로 지키면서도, 프로그램 실행 전 정적 코드 검사기(`mypy` 등)를 통해 인터페이스 규격이 맞는지 미리 컴파일 수준으로 체크할 수 있는 최고의 조율 지점을 획득했습니다.

## ☕ Java vs Python 스나이퍼 비교

### 타입 시스템의 근본적인 대결
*   **Java**: 철저한 **명목적 타이핑(Nominal Typing)** 시스템입니다. 한 클래스가 특정 타입의 패밀리가 되려면 무조건 `extends Parent` 또는 `implements Interface` 라고 선언문 상에 이름을 대놓고 명시해야만 합니다. 구조가 똑같아도 상속 이름표가 없으면 남남입니다.
*   **Python**: 런타임에는 이름 따위는 무시하는 **덕 타이핑**으로 자유롭게 동작하고, 개발 단계 정적 분석에서는 메서드 구조와 인터페이스 정의가 맞는지 대조하는 **구조적 타이핑(Protocol)**을 활용하여 유연성과 엄격성을 완벽히 양립시킵니다.

*   **`Type Hinting`**: 타입 힌팅. (파이썬 코드 내 변수, 함수 매개변수 및 반환값에 대해 권장하는 데이터 타입을 어노테이션 형태로 기록하여 정적 분석을 돕는 주석 기술입니다.)

## 17 코드에 달아주는 안전 명찰: 타입 힌트(Type Hint)와 테스트

파이썬은 변수에 "나는 평생 정수(int)만 받을 거야!" 하고 못 박지 않는 매우 자유로운 동적(Dynamic) 언어입니다. 아주 편하고 짜릿하지만, 실무에서 팀원들과 협업할 때 다른 사람이 숫자 대신 갑자기 문자열을 집어넣어 프로그램이 와장창 깨지는 대형 사고가 나기도 하죠. 

이런 불상사를 막기 위해, 코드를 실행하기 전 에디터 화면에 **"이 변수나 매개변수는 이런 타입만 넣어주세요"라고 팻말을 달아주는 기능**이 바로 **타입 힌트(Type Hint)**입니다.

### 1. 화살표와 콜론으로 명찰 달기 (Type Annotation)

파이썬 문법 상 변수 뒤에 콜론(`:`)을 붙이고, 함수 반환값 뒤에 화살표(`->`)를 사용하여 개발자가 의도하는 데이터의 종류(타입)를 메모해 둘 수 있습니다. 

```python
# 매개변수 a와 b는 정수(int)를 받고, 함수의 최종 결과도 정수(int)가 나온다고 명시!
def calculate_age(birth_year: int, current_year: int) -> int:
    return current_year - birth_year

# VS Code 같은 똑똑한 에디터는 아래처럼 문자를 넣으면 빨간 밑줄을 쫙 그어 경고해줍니다!
print(calculate_age("1990년", 2026)) 
```
> [!WARNING]
> 꼭 명심하세요. 파이썬의 타입 힌트는 어디까지나 사람과 에디터 모니터링을 위한 '힌트(주석)'일 뿐입니다. 실제 파이썬 엔진은 이를 쿨하게 무시하고 문자가 들어왔든 뭐가 들어왔든 코드를 **강제로 실행**시킵니다. 따라서 이 힌트 자체만으로는 프로그램의 런타임 보안을 막을 수 없고, 코딩 단계에서 실수를 덜어주는 보조 도구로 생각해야 합니다.

### 2. 디테일한 힌트를 위한 `typing` 모듈

만약 단순한 숫자가 아니라, "오직 정수만 옹기종기 모여있는 리스트"라고 확실히 못 박고 싶을 때는 파이썬 자체 내장 도구인 `typing` 모듈을 불러옵니다.

```python
from typing import List, Dict

# 이 상자 안에는 문자열(str)만 들어와야 합니다!
names_list: List[str] = ["Alice", "Bob", "Charlie"]

# 딕셔너리의 열쇠(Key)는 문자열(str), 알맹이(Value)는 정수(int)만 와야 합니다!
student_scores: Dict[str, int] = {"Alice": 100, "Bob": 80}
```

### 3. 이 설명서가 맞나? 자동 테스트기 (`doctest`)

함수 바로 아래에 큰 따옴표 3개 `"""` 로 묶어서 "이 함수는 이렇게 씁니다~" 하고 작성한 설명서를 **독스트링(Docstring)**이라고 부릅니다.
여기에 덤으로 Python 대화형 창(`>>>`)에서 실행하는 예제 코드를 함께 적어두면, 파이썬이 이 주석을 눈으로 읽고 **설명서에 적힌 결과가 실제 작동 결과와 똑같이 나오는지 자동으로 검사해주는 마법 기능**이 `doctest`입니다.

```python
def multiply(a, b):
    """
    이 함수는 두 숫자를 곱합니다.
    
    >>> multiply(5, 5)
    25
    >>> multiply(10, 2)
    20
    """
    return a * b
```
이렇게 주석을 예쁘게 달아두고, 터미널(명령 프롬프트)에서 아래처럼 마법의 주문을 외우면 됩니다.
`python -m doctest 파일명.py` 

만약 내가 짠 로직이 주석에 썼던 결과(25, 20)와 1이라도 다르면, 파이썬이 삑- 하고 터미널에 에러 문구를 뿜어주어 "네 설명서랑 코드가 안 맞아!"라고 알려줍니다. 버그를 잡는 아주 훌륭한 파수꾼입니다.
