# PART 13 고수들의 비밀 무기, 논리 연산과 if문 심화

단순히 `A == B` 수준의 조건을 넘어, 파이썬이 복잡한 논리식을 마주했을 때 내부적으로 어떻게 꼼수를 부리며 빠르게 계산해 내는지(단락 평가), 그리고 진짜 `True`/`False`가 아닌 값들도 어떻게 참과 거짓으로 판별하는지(Truthy & Falsy) 알아봅니다. 이 비밀을 깨달으면 코드가 마법처럼 짧아집니다.

# 40 파이썬의 게으른 계산법: 단락 평가(Short-circuit)

`and`와 `or` 연산자를 쓸 때 파이썬은 엄청난 지름길을 활용합니다. 결론이 이미 뻔하다면, 굳이 뒤쪽 코드는 쳐다보지도 않고 무시해버리는 것인데 이를 **단락 평가(Short-circuit evaluation)**라고 부릅니다.

### 1. and 의 단락 평가
`and`는 **양쪽이 모두 참이어야** 최종적으로 참이 됩니다. 만약 왼쪽 식이 `False`라면? 어차피 전체 결과는 무조건 `False`가 되므로 오른쪽 식은 아예 실행조차 하지 않습니다.

**코드: 안전한 딕셔너리 검사**
```python
user = {"name": "파이썬"}

# 만약 파이썬이 무식하게 양쪽을 다 검사한다면, 뒤쪽 user["age"] 에서 에러(KeyError)가 터집니다.
# 하지만 앞의 "age" in user 가 이미 False이므로, 뒤쪽 코드는 쳐다보지도 않고 그냥 넘어갑니다! 대박!
if "age" in user and user["age"] > 20:
    print("성인입니다.")
else:
    print("나이 정보가 없거나 미성년자입니다.")
```

### 2. or 의 단락 평가
반대로 `or`는 **어느 한 쪽만 참이어도** 전체가 참이 됩니다. 따라서 왼쪽 식이 `True`라면? 뒤쪽 식은 볼 것도 없이 최종 결과를 `True`로 확정 짓고 오른쪽 코드는 무시해버립니다.

# 41 진짜가 아닌 것들의 진실: Truthy 와 Falsy

`if`문 뒤에는 반드시 `True`나 `False`만 와야 할까요? 놀랍게도 파이썬은 숫자, 문자열, 리스트 등 세상 만물을 자체적으로 '참(True)'이나 '거짓(False)'으로 은밀하게 평가합니다.

### 텅 비면 거짓(Falsy), 무언가 채워져 있으면 참(Truthy)

파이썬의 절대 규칙입니다. 텅 비어있거나 0이라면 무조건 **거짓(False)** 취급입니다.
* **거짓 취급(Falsy)**: `0`, `0.0`, `""` (빈 문자열), `[]` (빈 리스트), `{}` (빈 딕셔너리), `None`
* **참 취급(Truthy)**: `1`, `-10`, `"안녕"`, `[1, 2]`, 심지어 띄어쓰기 한 칸 `" "` 도 무언가 들어있으므로 참입니다.

**REPL 실습: 데이터의 참/거짓 판별**
```python
>>> bool(0)
False
>>> bool(-99)
True
>>> bool([])
False
>>> bool([1])
True
```

이 규칙을 방금 배운 `or` 단락 평가와 기가 막히게 섞어 쓰면, 기본값을 세팅하는 마법의 한 줄 코드가 탄생합니다.

**코드: 닉네임 기본값 세팅하기**
```python
# 사용자가 이름 입력을 무시하고 그냥 엔터를 쳤다면?
# input()은 빈 문자열 "" 을 반환합니다. (Falsy)
# 앞이 False로 취급되므로, or 연산자는 뒤쪽의 '이름없는 용사'를 최종 결괏값으로 채택합니다!

nickname = input("닉네임을 입력하세요: ") or "이름없는 용사"

print(f"환영합니다, {nickname}님!")
```

위 코드를 실행하고 아무것도 적지 않은 채 엔터를 치면 에러 대신 멋지게 "이름없는 용사"가 세팅됩니다. 다른 복잡한 프로그래밍 언어 개발자들이 파이썬의 이 우아한 문법을 보면 눈물을 흘릴 정도입니다. 꼭 원리를 이해하고 써먹어 보세요!
