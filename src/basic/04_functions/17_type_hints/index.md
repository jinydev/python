# 17 코드에 달아주는 안전 명찰: 타입 힌트(Type Hint)와 테스트

파이썬은 변수에 "나는 평생 정수(int)만 받을 거야!" 하고 못 박지 않는 매우 자유로운 동적(Dynamic) 언어입니다. 아주 편하고 짜릿하지만, 실무에서 팀원들과 협업할 때 다른 사람이 숫자 대신 갑자기 문자열을 집어넣어 프로그램이 와장창 깨지는 대형 사고가 나기도 하죠. 

이런 불상사를 막기 위해, 코드를 실행하기 전 에디터 화면에 **"이 변수나 매개변수는 이런 타입만 넣어주세요"라고 팻말을 달아주는 기능**이 바로 **타입 힌트(Type Hint)**입니다.

## 1. 화살표와 콜론으로 명찰 달기 (Type Annotation)

파이썬 문법 상 변수 뒤에 콜론(`:`)을 붙이고, 함수 반환값 뒤에 화살표(`->`)를 사용하여 개발자가 의도하는 데이터의 종류(타입)를 메모해 둘 수 있습니다. 

```python
# 매개변수 a와 b는 정수(int)를 받고, 함수의 최종 결과도 정수(int)가 나온다고 명시!
def calculate_age(birth_year: int, current_year: int) -> int:
    return current_year - birth_year

# VS Code 같은 똑똑한 에디터는 아래처럼 문자를 넣으면 빨간 밑줄을 쫙 그어 경고해줍니다!
print(calculate_age("1990년", 2026)) 
```
> [!WARNING]
> 꼭 명심하세요. 파이썬의 타입 힌트는 어디까지나 사람과 에디터 모니터링을 위한 '힌트(주석)'일 뿐입니다. 실제 파이썬 엔진은 이를 쿨하게 무시하고 문자가 들어왔든 뭐가 들어왔든 코드를 **강제로 실행**시킵니다. 따라서 이 힌트 자체만으로는 프로그램의 런타임 보안을 막을 수 없고, 코딩 단계에서 실수를 덜어주는 보조 도구로 생각해야 합니다.

## 2. 디테일한 힌트를 위한 `typing` 모듈

만약 단순한 숫자가 아니라, "오직 정수만 옹기종기 모여있는 리스트"라고 확실히 못 박고 싶을 때는 파이썬 자체 내장 도구인 `typing` 모듈을 불러옵니다.

```python
from typing import List, Dict

# 이 상자 안에는 문자열(str)만 들어와야 합니다!
names_list: List[str] = ["Alice", "Bob", "Charlie"]

# 딕셔너리의 열쇠(Key)는 문자열(str), 알맹이(Value)는 정수(int)만 와야 합니다!
student_scores: Dict[str, int] = {"Alice": 100, "Bob": 80}
```

## 3. 이 설명서가 맞나? 자동 테스트기 (`doctest`)

함수 바로 아래에 큰 따옴표 3개 `"""` 로 묶어서 "이 함수는 이렇게 씁니다~" 하고 작성한 설명서를 **독스트링(Docstring)**이라고 부릅니다.
여기에 덤으로 Python 대화형 창(`>>>`)에서 실행하는 예제 코드를 함께 적어두면, 파이썬이 이 주석을 눈으로 읽고 **설명서에 적힌 결과가 실제 작동 결과와 똑같이 나오는지 자동으로 검사해주는 마법 기능**이 `doctest`입니다.

```python
def multiply(a, b):
    """
    이 함수는 두 숫자를 곱합니다.
    
    >>> multiply(5, 5)
    25
    >>> multiply(10, 2)
    20
    """
    return a * b
```
이렇게 주석을 예쁘게 달아두고, 터미널(명령 프롬프트)에서 아래처럼 마법의 주문을 외우면 됩니다.
`python -m doctest 파일명.py` 

만약 내가 짠 로직이 주석에 썼던 결과(25, 20)와 1이라도 다르면, 파이썬이 삑- 하고 터미널에 에러 문구를 뿜어주어 "네 설명서랑 코드가 안 맞아!"라고 알려줍니다. 버그를 잡는 아주 훌륭한 파수꾼입니다.
