# 13주차: 게임 개발 원리 - 실시간 상호작용 구현 🎮

우리는 이제 정적인 프로그램에서 벗어나, 실시간으로 화면이 변하고 사용자와 상호작용하는 **게임 개발**의 기초를 배웁니다. 게임은 일반 프로그램과 달리 '끝'이 정해져 있지 않고, 사용자가 종료할 때까지 무한히 반복되는 구조를 가집니다.

---

## 1. 게임 루프 (Game Loop)

게임의 심장은 **게임 루프**입니다. 게임은 1초에 수십 번(FPS, Frames Per Second) 다음과 같은 과정을 반복합니다.

![게임 루프 구조](./img/game_loop.svg)

### 1.1 게임 루프의 3단계
1.  **입력 처리 (Input):** 사용자가 키보드를 눌렀는지, 마우스를 움직였는지 확인합니다.
2.  **상태 업데이트 (Update):** 입력에 따라 캐릭터의 위치를 옮기고, 충돌을 체크하고, AI의 행동을 결정합니다.
3.  **화면 그리기 (Render):** 업데이트된 상태를 바탕으로 화면에 그림을 그립니다.

---

## 2. 델타 타임 (Delta Time)의 중요성

컴퓨터마다 성능이 다릅니다. 어떤 컴퓨터는 1초에 60번 루프를 돌고, 어떤 컴퓨터는 144번 돕니다. 만약 단순히 `x += 1`이라고 코드를 짜면, 성능이 좋은 컴퓨터에서 캐릭터가 훨씬 빠르게 움직이게 됩니다.

이를 해결하기 위해 **델타 타임(지난 프레임부터 현재 프레임까지 걸린 시간)**을 사용합니다.

**공식:** `이동 거리 = 속도 * 델타 타임`

```python
# 잘못된 예: 컴퓨터 성능에 따라 속도가 달라짐
player.x += 5 

# 올바른 예: 어떤 컴퓨터에서든 동일한 속도로 이동
player.x += speed * delta_time
```

## 3. 간단한 게임 구조 설계 (Pygame 예시)

파이썬에서 게임을 만들 때 가장 많이 사용하는 `pygame` 라이브러리의 기본 구조입니다.

```python
import pygame

pygame.init()
screen = pygame.display.set_mode((800, 600))
clock = pygame.time.Clock()
running = True

while running:
    # 1. 입력 처리
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    # 2. 상태 업데이트
    # (캐릭터 이동, 충돌 체크 등)

    # 3. 화면 그리기
    screen.fill((255, 255, 255)) # 배경 흰색
    pygame.draw.circle(screen, (0, 0, 255), (400, 300), 20) # 파란 원 그리기
    pygame.display.flip()

    # 델타 타임 계산 및 FPS 제한 (60 FPS)
    clock.tick(60)

pygame.quit()
```

## 🔍 Deep Dive: 게임 루프(Game Loop) 아키텍처와 프레임 레이트 독립성, 그리고 델타 타임의 물리 연산

게임을 개발할 때는 일반 프로그램과 완전히 다른 아키텍처가 동원됩니다.
- **게임 루프 (Game Loop)**: "입력 수신 ➡️ 물리 상태 업데이트 ➡️ 화면 렌더링" 이 세 단계를 초당 60번 이상 무한히 반복 구동하는 루프 구조입니다.
- **프레임 레이트 독립성 (Frame-rate Independence)**: 컴퓨터 사양이 다르면 초당 프레임 수(FPS)가 달라집니다. 고사양 컴퓨터에서 120 FPS로 돌린다고 해서 캐릭터가 저사양 컴퓨터(30 FPS)보다 4배 빠르게 움직이면 안 되겠죠.
- **Delta Time (델타 타임)**: 이전 프레임부터 현재 프레임까지 흐른 실제 시간(`dt`)을 구한 뒤, 모든 이동 수식에 이 델타 타임을 곱해 줍니다 (`position += speed * dt`). 이렇게 하면 FPS가 30이든 120이든 상관없이 모든 컴퓨터에서 캐릭터는 1초에 정확히 설정된 거리만큼 균등하게 이동하는 완성형 게임 물리 엔진이 성립됩니다.

## ☕ Java vs Python/C++ 스나이퍼 비교

### 게임 엔진 개발 플랫폼
*   **Java**: 과거 모바일용 피처폰 게임의 지배자였으며, 대표적으로 유명한 마인크래프트(Minecraft)가 Java와 LWJGL(Lightweight Java Game Library) 기반으로 작성되었습니다. 그러나 모던 대규모 3D 게임 시장에서는 가상머신 GC 병목 현상 때문에 메이저하게 채택되지 못합니다.
*   **C++**: 업계 표준인 언리얼 엔진(Unreal Engine)이나 자체 고성능 게임 물리 엔진 개발의 독보적인 주류 언어입니다. 메모리 포인터 제어와 하드웨어 GPU 연산을 한계까지 끌어다 씁니다.
*   **Python**: 상용 대형 게임 제작용은 아니지만, 프로그래밍 및 게임 개발 기초 수학적 시뮬레이션 학습을 위해 **`pygame`** 모듈을 사용하여 2D 인디 게임 아키텍처를 가장 빠르고 유연하게 구현하여 프로토타이핑해 볼 수 있는 최고의 교육용 플랫폼을 제공합니다.

## 코딩 영단어 학습 📝

*   **`Game Loop`**: 게임 루프. (게임 프로그램의 라이프사이클 내내 사용자 키 입력, 인공지능 상태 변화, 화면 갱신을 지속적으로 반복 통제하는 게임 엔진 아키텍처 핵심 루프입니다.)
*   **`Delta Time`**: 델타 타임. (컴퓨터 성능 격차에 무관하게 모든 디바이스에서 캐릭터 이동 속도를 동일하게 고정하기 위해 계산한 프레임 간의 실제 경과 시간입니다.)
*   **`FPS` (Frames Per Second)**: 초당 프레임 수. (화면 장치나 게임 렌더러 엔진이 1초당 모니터 화면에 뿌려주는 연속적인 정지 이미지 정밀도의 숫자입니다.)
