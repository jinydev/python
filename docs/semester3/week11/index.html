11주차: 비동기 프로그래밍 (1) - asyncio와 코루틴 ⚡

우리는 멀티스레딩과 멀티프로세싱을 배웠습니다. 하지만 수천 개의 네트워크 연결을 처리해야 하는 서버를 만들 때, 수천 개의 스레드를 만드는 것은 메모리 낭비가 너무 심합니다. 이를 해결하기 위해 등장한 것이 비동기 프로그래밍(Asynchronous Programming)입니다.

1. 비동기 프로그래밍이란?

비동기 프로그래밍은 “어떤 작업이 끝날 때까지 기다리지 않고, 다른 작업을 먼저 수행하는 방식”입니다.

#

🔍 Deep Dive: 협력적 멀티태스킹(Cooperative Multitasking)과 싱글스레드 이벤트 루프 원리

비동기 프로그래밍은 멀티스레드나 멀티프로세스 없이도 초고속 동시성을 내는 마법입니다.

  • 협력적 멀티태스킹 (Cooperative Multitasking): 운영체제가 강제로 CPU 제어권을 빼앗아 스레드를 교체하는 선점형(Preemptive) 방식과 다릅니다. 비동기 프로그램은 코루틴(Coroutine) 스스로가 “나 여기서 웹 응답 기다려야 하니 제어권 돌려줄게” 라고 양보(await)하는 협력적 메커니즘으로 돕니다.
  • 싱글스레드 이벤트 루프: 단 하나의 스레드가 이벤트 루프라는 감시 회전판을 무한히 돌리며, 대기 중이던 네트워크 데이터가 도착하면 즉시 등록된 콜백 함수를 실행합니다. 컨텍스트 스위칭 오버헤드가 전무하여 초고성능 웹서버(Node.js, FastAPI 등)의 근간이 됩니다.

☕ Java vs Python 스나이퍼 비교

비동기 처리 패러다임의 비교

  • Java: 비동기 논블로킹 처리를 위해 CompletableFuture 객체 빌더를 사용하거나, Project Loom을 통해 가볍고 엄청나게 많은 개수를 띄울 수 있는 가상 스레드(Virtual Thread - Fiber)를 도입하여 굳이 비동기 복잡성 없이 기존 동기식 코드 스타일로 수만 개의 동시성을 처리하는 시대로 나아가고 있습니다.
  • Python: 언어 차원에서 async/await 문법과 asyncio 내장 모듈을 도입하여 싱글스레드 기반의 논블로킹 비동기 프로그래밍 모델을 명확히 제시하고 이를 FastAPI 등 모던 성능 생태계로 안착시켰습니다.

코딩 영단어 학습 📝

  • Async (Asynchronous): 비동기. (작업의 시작과 끝을 동기적으로 기다리지 않고, 요청만 보낸 뒤 제어권을 반환받아 다른 유익한 연산을 즉시 이어나가는 논블로킹 구동 모델입니다.)
  • Coroutine: 코루틴. (일반적인 함수(Subroutine)와 달리, 실행 도중 임의의 지점에서 일시 중단(await)하고 나중에 그 중단 지점 상태 그대로 다시 실행을 이어갈 수 있는 특수한 비동기 협력 함수 구조입니다.)
  • Event Loop: 이벤트 루프. (비동기 작업의 발생, 대기, 완료 이벤트를 계속해서 감시하고 순회하며 완료된 이벤트를 대기 중인 콜백 함수에 전달해 즉시 구동시켜 주는 비동기 핵심 심장 루프입니다.)

65 핑퐁 게임하듯 대화하는 함수: 코루틴(coroutine)

이전 장에서 배운 제너레이터는 함수의 흐름을 일시 정지하고 밖에 있는 사람(우리가 쓴 메인 코드)에게 짠! 하고 “데이터를 꺼내주는” 멋진 재주(yield)를 갖고 있었습니다. 그런데 파이썬 개발자들은 문득 아주 재미있고 기발한 생각을 냈습니다.

“함수 밖으로 데이터를 꺼내는 것뿐만 아니라, 거꾸로 일시 정지해 있는 함수 안으로 새 데이터를 쏙 밀어 넣을 수는 없을까?”

이 기발한 역발상으로 탄생한 것이 바로 핑퐁(탁구) 게임처럼 밖과 안이 양방향으로 데이터를 주고받으며 통신하는 코루틴(Coroutine)입니다!

1. 받기만 하는 yield

제너레이터에서는 yield 값 형태로 응답을 밖으로 보냈었죠? 코루틴에서는 변수 = yield 형태로 위치를 바꾸어, 함수 밖에서 자기를 향해 던져주는 데이터를 두 팔 벌려 받습니다.

밖에서 이 일시 정지된 코루틴 함수 안으로 새 데이터를 던져 넣을 땐 send() 라는 강력한 전송 메서드를 사용합니다.

def ping_pong_robot():
    while True:
        # 누군가 밖에서 나한테 데이터를 던지면 그 값을 ball에 쏙 저장합니다.
        ball = yield 
        print(f"야호! 로봇이 [{ball}](을)를 강하게 튕겨냅니다!")

# 코루틴 로봇 전원 켜기
robot = ping_pong_robot()

# [중요!] 로봇을 첫 가동시키기 위해선 준비 과정이 필요합니다.
# 처음에 비어있는 값(None)을 던져서 첫 yield 대기선까지 도착하게 만들어야 합니다!
robot.send(None) 
# (next(robot) 이라고 써도 똑같은 효과가 납니다)

# 자, 이제 준비된 로봇에게 핑퐁 공(데이터)을 밖에서 던져 넣어봅시다!
robot.send("핑")       # 야호! 로봇이 [핑](을)를 강하게 튕겨냅니다!
robot.send("퐁!")      # 야호! 로봇이 [퐁!](을)를 강하게 튕겨냅니다!
robot.send("불꽃 스매쉬!") # 야호! 로봇이 [불꽃 스매쉬!](을)를 강하게 튕겨냅니다!

2. 핑퐁을 치며 밖으로 응답 뱉기 (산출과 입력을 동시에!)

코루틴의 진짜 마법은 데이터를 받는 것(yield 왼쪽에 변수)과 동시에 다른 가공된 값을 밖으로 산출(yield 오른쪽에 결과값)할 수 있다는 점입니다.

반환받는변수 = yield 산출할값 처럼 양옆으로 적으면, 나에게 들어온 공(입력)을 받아 내부 로직으로 똑똑하게 가공한 다음, 다시 밖으로 스파이크(결과)를 날릴 수 있습니다.

def running_average_bot():
    """들어오는 숫자들을 기억하여 그때그때의 평균을 대답하는 로봇"""
    total = 0
    count = 0
    average = 0
    
    while True:
        # 1. 오른쪽 average(현재 평균)를 밖으로 던져줍니다.
        # 2. 그리고 일시 정지! 누군가 숫자를 send() 하면 그걸 new_number에 저장
        new_number = yield average
        
        # 내부 로직 가동!
        total += new_number
        count += 1
        average = total / count

# 1. 평균 계산기 전원 켜기
avg_bot = running_average_bot()
# 2. 예열하기 (첫 번째 yield 대기선까지 달려서 초기값 0을 받아냄)
print("초기 상태:", avg_bot.send(None)) 

# 3. 숫자들을 밖에서 슉슉 던져주면, 바로바로 뱃속에서 평균을 계산해 대답합니다!
print("10 입력 -> 평균:", avg_bot.send(10)) # 평균: 10.0
print("20 입력 -> 평균:", avg_bot.send(20)) # 평균: 15.0
print("90 입력 -> 평균:", avg_bot.send(90)) # 평균: 40.0

3. 코루틴의 전원 끄기 (close)

위의 핑퐁 로봇들은 무한 루프(while True) 대기 상태에 있기 때문에 내버려 두면 프로그램이 끝날 때까지 메모리 한쪽에서 계속 기다립니다. 일이 끝나면 친절하게 전원을 꺼주는 예의가 필요합니다.

# 퇴근할 시간이 되면 로봇을 끕니다.
avg_bot.close()

# 끈 로봇한테 또 데이터를 던지면?
# "더 이상 일 안 해요!" 라는 StopIteration 경고 에러가 터집니다.
# avg_bot.send(100)  (에러 발생!)

이 코루틴 특유의 “정지 -> 응답 -> 재개 -> 통신” 구조는, 훗날 여러분이 수만 명의 동시 접속자를 처리하는 서버 통신이나 대용량 데이터 비동기 다운로드(파이썬의 마법 비기 async/await)를 다룰 때 매끄럽게 돌아가게 해주는 가장 거대한 심장부 역할을 합니다!

4. 핑퐁 게임하듯 대화하는 함수: 코루틴 (coroutine)

방금 배운 제너레이터는 함수의 흐름을 일시 정지하고 밖에 있는 사람(우리가 쓴 메인 코드)에게 짠! 하고 “데이터를 꺼내주는” 멋진 재주(yield)를 갖고 있었습니다. 그런데 파이썬 개발자들은 문득 이런 재밌는 생각을 했습니다.

“함수 밖으로 데이터를 꺼내는 것뿐만 아니라, 거꾸로 일시 정지해 있는 함수 안으로 새 데이터를 쏙 밀어 넣을 수는 없을까?”

이 기발한 역발상으로 탄생한 것이 바로 핑퐁 게임처럼 밖과 안이 데이터를 주고받으며 대화하는 코루틴(Coroutine)입니다!

4.1. 받기만 하는 yield

제너레이터에서는 yield 값 형태로 응답을 밖으로 보냈었죠? 코루틴에서는 변수 = yield 형태로 바뀌어, 함수 밖에서 자기를 향해 던져주는 데이터를 두 팔 벌려 받습니다.

밖에서 이 일시 정지된 코루틴 함수 안으로 데이터를 던져 넣을 땐 send() 라는 강력한 메서드를 사용합니다.

def ping_pong_robot():
    while True:
        # 누군가 밖에서 나한테 데이터를 파싱해주면 그 값을 ball에 저장합니다.
        ball = yield 
        print(f"야호! 로봇이 [{ball}]을 튕겨냅니다!")

# 코루틴 로봇 준비
robot = ping_pong_robot()

# [주의사항!] 로봇을 처음 가동시키기 위해선 준비 과정이 필요합니다.
# 처음에는 비어있는 값(None)을 던져서 yield 부분까지 도착하게 만들어야 합니다!
robot.send(None) 

# 이제 로봇에게 핑퐁 공(데이터)을 던져 넣어봅시다!
robot.send("핑")     # 야호! 로봇이 [핑]을 튕겨냅니다!
robot.send("퐁!")    # 야호! 로봇이 [퐁!]을 튕겨냅니다!
robot.send("스매시!")# 야호! 로봇이 [스매시!]을 튕겨냅니다!

4.2 코루틴의 라이프 사이클 관리 (close, throw)

이 핑퐁 로봇은 계속 대기 상태(while True)에 있기 때문에 놔두면 프로그램이 끝날 때까지 멈춰있습니다. 친절하게 전원을 꺼주는 작업이 필요합니다.

  • close(): 코루틴을 강제로 종료시킵니다.
  • throw(): 코루틴 안쪽으로 폭탄(예외/Error)을 던져 넣어 강제 예외 처리를 유발하게 만듭니다.
# 퇴근할 시간이 되면 로봇을 끕니다.
robot.close()

# 끈 로봇한테 또 데이터를 던지면?
# "더 이상 못 받아요!" 라는 StopIteration 에러가 터집니다.
# robot.send("막타")  (에러 발생!)

4.3 핑퐁을 치며 계산 누적하기 (산출과 입력을 동시에!)

코루틴의 진짜 마법은 데이터를 받는 것(yield 왼쪽에 변수)과 동시에 다른 값을 밖으로 산출(yield 오른쪽에 결과값)할 수 있다는 점입니다.

반환받는값 = yield 산출할값 처럼 적으면, 나에게 들어온 공(입력)을 받아 내부에서 멋지게 가공한 다음, 다시 밖으로 스파이크(결과)를 날릴 수 있습니다.

def running_average_bot():
    total = 0
    count = 0
    average = 0
    
    while True:
        # 시작 시 average(0)를 밖으로 주고 일시 정지합니다.
        # 누군가 나에게 새 숫자를 send() 하면 그걸 new_number에 저장합니다.
        new_number = yield average
        
        # 내부 로직 가동!
        total += new_number
        count += 1
        average = total / count

# 평균 계산기 가동
avg_bot = running_average_bot()
print(avg_bot.send(None)) # 준비 완료 후 최초 초기값(0) 반환

# 숫자들을 쭉 던져주면 그동안의 평균을 계산해서 바로바로 응답합니다!
print(avg_bot.send(10)) # 평균 10.0
print(avg_bot.send(20)) # 평균 15.0
print(avg_bot.send(90)) # 평균 40.0

이 코루틴의 특유의 “정지-응답-재개-통신” 구조는 훗날 서버 네트워크 접속, 데이터 동시 다운로드 같은 아주 복잡한 일(비동기 프로그래밍, async/await)을 매끄럽게 돌아가게 해주는 핵심 심장부가 됩니다!
