14주차: 배포 및 패키징 (1) - 내 코드를 라이브러리로 만들기 📦

우리는 이제 훌륭한 기능을 가진 코드를 짤 수 있습니다. 하지만 내 컴퓨터에서만 돌아가는 코드가 아니라, 전 세계 사람들이 pip install로 설치해서 사용할 수 있는 라이브러리로 만들려면 어떻게 해야 할까요?

1. 패키징 (Packaging)이란?

패키징은 소스 코드를 배포 가능한 형태로 묶는 과정입니다. 단순히 파일을 압축하는 것이 아니라, 버전 정보, 의존성(필요한 다른 라이브러리), 메타데이터를 함께 포함시키는 것입니다.

1.1 Wheel (.whl) 포맷

파이썬의 표준 배포 포맷은 Wheel입니다. Wheel은 빌드된 바이너리 형태로, 사용자가 설치할 때 컴파일 과정 없이 빠르게 설치할 수 있게 해줍니다.

2. 현대적 설정 파일: pyproject.toml

과거에는 setup.py 파일을 사용했지만, 현재 파이썬 커뮤니티는 pyproject.toml이라는 표준 설정 파일을 권장합니다.

2.1 pyproject.toml 작성 예시

[build-system]
requires = ["setuptools", "wheel"]
build-backend = "setuptools.build_meta"

[project]
name = "my_awesome_lib"
version = "0.1.0"
description = "세상에서 가장 멋진 파이썬 라이브러리"
dependencies = [
    "requests >= 2.25.1",
    "numpy",
]
  • build-system: 어떤 도구를 사용하여 패키지를 빌드할지 정의합니다.
  • project: 패키지의 이름, 버전, 설명 및 필수 의존성 라이브러리를 정의합니다.

3. 빌드 도구 사용하기

패키지를 빌드하기 위해 build 모듈을 사용합니다.

빌드 과정:

  1. pip install build 설치
  2. python -m build 실행 $\rightarrow$ dist/ 폴더에 .whl 파일과 .tar.gz 파일이 생성됩니다.

✍️ 이번 주 연습 문제

문제 1. 자신의 이름과 버전(0.1.0)을 넣은 간단한 pyproject.toml 파일을 작성해 보세요.

문제 2. build 모듈을 사용하여 자신의 프로젝트를 빌드하고, dist/ 폴더에 어떤 파일들이 생성되는지 확인해 보세요.

문제 3. (심화) setup.py 방식과 pyproject.toml 방식의 가장 큰 차이점이 무엇인지, 왜 파이썬 커뮤니티가 pyproject.toml로 전환하고 있는지 조사하여 설명해 보세요.

🔍 Deep Dive: pyproject.toml(PEP 518) 통합 패키징 명세의 혁신과 모던 빌드 백엔드

예전 파이썬 프로젝트들은 빌드나 설치 설정을 위해 무조건 setup.py 파일 안에 절차적 코드를 구구절절 적었습니다. 이는 보안상 악성 코드가 실행될 수 있고 빌드 도구 간 호환성이 낮다는 단점이 있었습니다.

  • pyproject.toml (PEP 518): 프로젝트의 빌드 의존성 및 각종 메타데이터를 선언적이고 정형화된 TOML 텍스트 포맷 단 하나로 기술하는 표준입니다.
  • 빌드 백엔드(Build Backend)의 다양화: 기존의 무거운 setuptools 일변도에서 벗어나, 이제는 poetry-core, hatchling, flit 등 속도가 매우 빠르고 기능이 풍부한 모던 빌드 엔진들을 프로그래머가 입맛에 맞게 자유롭게 선택하여 빌드 아키텍처를 교체할 수 있는 유연한 생태계가 안착되었습니다.

☕ Java vs Python 스나이퍼 비교

빌드 명세와 디펜던시 관리 체계

  • Java: 전통의 강자인 Maven의 pom.xml(XML 기반)이나 Gradle의 build.gradle(Groovy/Kotlin DSL 기반)을 명세서로 삼아 빌드 라이프사이클을 통제하고 외부 중앙 저장소(Maven Central)에서 라이브러리를 동적으로 다운받아 묶어냅니다.
  • Python: 예전의 난잡한 setup.py, requirements.txt, Pipfile 등을 모조리 pyproject.toml 표준 문서 하나로 통합하여 가독성과 이식성을 극대화하고 있으며, 빌드 백엔드는 wheel 포맷의 배포판을 최종 생성합니다.

코딩 영단어 학습 📝

  • Packaging: 패키징. (내가 짠 소스 코드와 필요한 외부 종속 모듈들을 다른 컴퓨터나 환경에 즉시 설치하여 바로 사용할 수 있는 단일 배포 꾸러미(패키지) 형태로 조립하고 다듬는 마감 공정입니다.)
  • Wheel: 휠. (파이썬에서 컴파일이나 소스 빌드 없이 즉각적인 고속 설치를 보장하기 위해 미리 빌드되어 패키징된 바이너리 중심의 공식 배포 아카이브 포맷(.whl)입니다.)
  • PyPI (Python Package Index): 파이썬 패키지 색인. (전 세계 모든 개발자가 만든 유용한 파이썬 오픈소스 패키지들이 모여 업로드되고 전 세계 컴퓨터로 유통되는 피프(pip) 전용 중앙 백화점 저장소입니다.)
