11주차: 패키지 구조 설계 - 대규모 프로젝트 관리 📦

우리는 지금까지 개별 파일(모듈)을 만들어 사용했습니다. 하지만 프로젝트 규모가 커져 수십, 수백 개의 파일이 생기면 단순히 폴더에 넣는 것만으로는 부족합니다. 체계적인 패키지 구조를 설계하여 코드의 가독성과 유지보수성을 높이는 방법을 배웁니다.

1. 패키지 (Package)란?

패키지는 여러 모듈을 계층적으로 묶어놓은 디렉토리(폴더)입니다. 패키지를 사용하면 이름 충돌을 방지하고, 기능별로 코드를 그룹화할 수 있습니다.

1.1 __init__.py의 역할

폴더 안에 __init__.py 파일이 있으면 파이썬은 이 폴더를 일반 폴더가 아닌 ‘패키지’로 인식합니다.

  • 초기화: 패키지가 임포트될 때 가장 먼저 실행됩니다.
  • 공개 API 설정: __all__ 변수를 정의하여 from package import *를 했을 때 어떤 모듈을 가져올지 결정할 수 있습니다.

2. 임포트 방식: 절대 경로 vs 상대 경로

패키지 내부에서 다른 모듈을 가져올 때 두 가지 방식을 사용할 수 있습니다.

2.1 절대 경로 (Absolute Import)

프로젝트의 루트(최상위)부터 경로를 모두 적어주는 방식입니다.

# my_app/core.py에서 utils.py를 가져올 때
from my_app.utils import helper_func
  • 장점: 경로가 명확하여 가독성이 좋고, 파일 위치가 바뀌지 않는 한 안전합니다.
  • 단점: 패키지 이름이 길어지면 코드가 지저분해집니다.

2.2 상대 경로 (Relative Import)

현재 파일의 위치를 기준으로 경로를 지정하는 방식입니다. (.은 현재 폴더, ..은 상위 폴더)

# my_app/core.py에서 utils.py를 가져올 때
from .utils import helper_func
  • 장점: 패키지 이름을 바꿔도 내부 코드를 수정할 필요가 없습니다.
  • 단점: 파일을 다른 폴더로 옮기면 경로가 깨지며, 스크립트로 직접 실행할 때 에러가 발생할 수 있습니다.

3. 🔍 Deep Dive: 순환 참조 (Circular Import) 문제

패키지를 설계하다 보면 A 모듈이 B 모듈을 임포트하고, 동시에 B 모듈이 A 모듈을 임포트하는 순환 참조 상황이 발생할 수 있습니다.

결과: ImportError 또는 AttributeError가 발생하며 프로그램이 멈춥니다.

해결 방법:

  1. 설계 수정: 공통으로 사용하는 기능을 제3의 모듈(C 모듈)로 분리하여 A와 B가 모두 C를 임포트하게 합니다. (가장 권장됨)
  2. 지연 임포트 (Deferred Import): 함수 내부에서 import를 수행하여 실행 시점에만 모듈을 불러옵니다.

🔍 Deep Dive: 네임스페이스 패키지(PEP 420)와 임포트 임시 저장소 sys.modules

파이썬의 모듈 임포트 동작에는 놀라운 시스템적 절차가 숨어 있습니다.

  • 임포트 캐시: 모듈을 최초 import하면 파이썬은 모듈을 컴파일한 객체를 sys.modules라는 딕셔너리에 캐싱해 둡니다. 두 번째 호출부터는 디스크를 읽지 않고 이 메모리 캐시에서 직접 주소를 반환하여 속도를 극한으로 끌어올립니다.
  • 네임스페이스 패키지 (Namespace Packages): 기존 패키지들은 폴더 안에 무조건 __init__.py 파일이 있어야만 인식되었지만, 파이썬 3.3(PEP 420)부터는 이 파일이 없어도 폴더를 모듈식 패키지로 임포트할 수 있습니다. 이를 통해 서로 다른 디렉터리에 물리적으로 떨어져 있는 여러 하위 폴더들을 하나의 논리적 패키지명(Namespace)으로 묶어서 배포하고 공유하는 고급 아키텍처 구성이 가능해졌습니다.

☕ Java vs Python 스나이퍼 비교

임포트와 패키징 구조

  • Java: 패키지는 실제 물리적인 디렉터리 경로와 클래스 파일 내부의 package 선언과 완전히 일치해야 합니다. 클래스 패스(Classpath) 경로를 설정해 컴파일러가 모든 컴포넌트의 위치를 엄격히 검사하여 빌드합니다.
  • Python: sys.path라는 런타임 경로 환경 리스트를 이용합니다. 이 리스트에 폴더 주소만 추가해 두면, 디렉터리 구조가 다소 상이하거나 파일 내부 패키지 선언문이 없어도 인터프리터가 동적으로 탐색하여 바인딩해 줍니다.

코딩 영단어 학습 📝

  • Package: 패키지. (여러 모듈 파일을 폴더 단위로 묶어서 하나의 라이브러리로 구조화한 디렉터리 체계입니다.)
  • Namespace: 네임스페이스, 이름공간. (변수나 함수, 클래스 등이 저장되는 런타임 이름 맵핑 공간으로, 서로 이름이 겹쳐서 발생하는 네이밍 충돌을 예방해 줍니다.)
  • Relative Import: 상대 경로 임포트. (현재 파일의 위치를 기준으로 다른 모듈을 . 또는 ..과 같은 지시자를 사용하여 간편하게 끌어다 쓰는 패키징 기법입니다.)
